# 续算接口验收报告

## 结论

WannierBerri 1.8.0 定制源码的续算接口、首轮恢复和 Ray 收集优化已实现。
开发与计算均使用隔离环境。原计算任务及原环境保留。

## 第 0 轮未完成的专项验证

使用 84 个初始 K 点，覆盖：

| 场景 | 检查内容 |
| --- | --- |
| 缺少旧 K 点清单 | 已保存 0、1、42、57、83、84 个结果 |
| 乱序与编号空洞 | 随机顺序保存 57 个点，只补齐剩余点 |
| 新版中断 | 在第 0、1、41、83 个结果落盘后中断 |
| 多次续算中断 | 39 个旧结果，恢复新增 7 个后中断，再新增 11 个后中断 |
| 损坏与缺失混合 | 4 个缺失文件及 3 个截断文件，隔离后补算 |
| 结果齐全、轮次未完成 | 在完成标记前中断，恢复时不重算任何点 |
| 首个检查点尚未发布 | 在元数据或清单重命名边界中断后恢复 |

测试记录每次实际计算的坐标，要求所有缺失点恰好计算一次，已有有效文件保持
字节不变。恢复后再次恢复不计算任何点。继续两轮自适应细化后的选点、权重
与连续运行逐项相同；原始与平滑结果满足 `rtol=1e-10, atol=1e-12`。

完整测试还覆盖后续轮次中断、历史迭代、目录迁移、配置冲突、原子写入、
单写入者锁、只读 CLI、最终迭代换算及部署回滚。
另用 1e-10 的权重验证细化时旧贡献被正确移除，修复原版舍弃微小权重差的累加问题。

## 真实 CrSe 网格及旧结果

- 原参数重建 `NKdiv=[155,155,155]`、`NKFFT=[11,11,11]`。
- **620,775 个权重逐项完全相等，总和为 1。**
- 动态快照发现 **617,483 个结果文件、3,292 个缺失编号**。
  此处是文件数量；没有宣称全部旧张量均已通过重算。
- 抽查八个已有结果，覆盖四类权重和不同编号区间；逐点记录保留在私有验收目录。
- **八点全部通过：IMD/QMD 的 `data` 和 `dataSmooth` 最大绝对误差均为 0。**
- 重算使用独立目录里的稳定副本；复制前后核验文件属性和 SHA-256。
  主进程与 Ray worker 的导入路径、提交和全部部署文件哈希一致。

七点在并行作业内通过后，该作业因内存限制退出。剩余一点使用独立作业重算通过；
两次重算的包文件哈希完全相同，权重文件与该点的副本哈希也相同。
[公开汇总误差](../provenance/crse-validation.json) 记录了验收结论；完整逐点记录不入库。
原 pickle 缺少坐标及完整输入指纹，抽查为编号映射提供证据，但不构成全部文件来源的证明。
生产切换仍须在原进程停止写入后，完成最终复制、全文件校验和只读检查。

## Ray 收集与小模型

49,999 个轻量模拟任务验证了每个结果只取回、写入一次，已完成点不提交，
待处理引用最多 256 个。测试不再依赖对全部历史引用的逐批成员扫描。
最近一次开发测试耗时 0.256 秒，Python 分配峰值约 2.9 MB。
这些数字衡量收集逻辑开销，不表示真实 MQM 计算加速比。

小模型原版连续运行与新版连续运行结果完全一致。实际 Ray 并行结果也完全一致；
早期缺失点恢复对比最大绝对误差为 4.44e-16。
最终部署版本额外执行全套测试、原版对照及实际 Ray 回归，详见下方最终核验记录。

## 原版第 1 轮真实对照

在原始 `wberri_v1.8` 环境中复用完整第 0 轮结果，独立执行一轮自适应细化。
原版和续算版都从 620,775 个点增加到 620,791 个点，只新增 16 个点；六个
自适应指标分别集中到父点 331399 和 350911。两个版本的父点、16 个子点坐标
和全部权重逐项相同。

最终 IMD 原始及重建平滑结果最大绝对误差为 0；QMD 两项均为
`4.440892098500626e-16`，满足 `rtol=1e-10, atol=1e-12`。两类文本输出逐字节
相同。原环境源码逐文件与记录基线一致。为避免原版已知的全量 old-old 二次
遍历，对照仅将等价点去重循环替换为语义相同的增量遍历；选点、物理计算器、
对称化、权重更新和结果累加均使用原版实现。公开指标见
[原版第 1 轮对照记录](../provenance/original-v1.8-iteration1.json)。

## 资源与失败记录

所有验收作业均为单节点，每个时限不超过两小时。
此前两个预备作业分别因 Ray 临时路径过长、PointGroup 接口使用错误退出，
已修复后重试。内存退出后只重算未通过的那个点，保留七点证据。
原生产作业没有被取消，也没有提交替代生产作业。
